## 配置约定

运行配置固定在本工具源码的 `workspace_manager/config/config.yaml`。默认值来自 `core/config_store.py`，同目录提供 `config.example.yaml`。不采用旧文档中的 XDG 四层配置方案，不向安装资源目录写状态。

源码定位使用显式源码根目录环境变量、实际模块源码路径以及当前安装前缀所属工作空间的有限范围查找。多候选或源码不存在时报告问题；不根据正在管理的工作空间猜测配置位置。

保留本地偏好和包选择，运行配置取消版本控制跟踪。源码配置缺失时创建空白工作空间的默认配置，不自动导入旧安装目录；仅有旧安装配置的用户需关闭程序后主动复制到源码配置位置。已有旧格式源码配置仍会迁移并保留备份，旧勾选全部作为主动目标。配置保存保留类型校验、原子替换、独立锁及外部修改检测。

工作空间路径在内存中统一为规范化绝对路径。写入时仅将当前用户主目录及其子目录转换为 `~`，同时覆盖 `workspace_path` 和 `workspaces` 的键；主目录以外的路径保持原位置。转换按目录关系判断，不作字符串前缀替换。不同路径写法规范化为同一工作空间时，包选择取并集，其他重复字段采用后出现的值。继续兼容配置版本 2，GUI、扫描、构建和清理沿用绝对路径。

公开示例和代码默认值不包含工作空间历史。配置备份保留原始内容，新备份以 `0600` 权限创建，已有本机备份收紧为 `0600`。运行配置、备份、锁、临时文件及 Python 缓存均不应进入受控文件清单；原已跟踪缓存取消跟踪并保留本机内容。分享使用公开示例及审查后的 Git 提交，整目录打包和历史提交需要分别考虑。

## 职责划分

- `core/models.py`：包、依赖、工作空间快照、构建请求、进程结果。
- `core/config_store.py`：源码定位、默认值、迁移、读写与版本保护。
- `core/package_scanner.py`：colcon 查询参数与输出、清单条件、元数据摘要、支持范围校验。
- `core/dependency_graph.py`：清单关系及迭代式闭包。
- `core/build_plan.py`：环境快照、固定参数、安装布局与构建前置检查。
- `core/cleaner.py`：删除计划、目录身份、符号链接和删除结果。
- `core/locks.py`：配置与工作空间协作锁，不删除锁文件。
- `gui/process_runner.py`：QProcess、增量日志、取消升级和唯一终态。
- `process_launcher.py`：标准库 Linux 会话启动和进程组存活检查。
- 主窗口：状态流、用户目标、依赖校核、UI 回填、范围确认和关闭衔接。

核心模块不导入 Qt 或 rclpy。安装入口负责注入 ament 前缀、创建配置存储及最终销毁节点。

## 行为与影响

1. 候选工作空间扫描完成后才替换当前状态；无效目录保持原状态。
2. 用户目标与自动依赖分离。自动依赖不可直接取消；刷新保留目标，按工作空间保存。
3. colcon 发现与选择是实际构建集合的依据。清单图保留依赖类型及外部信息，不宣称覆盖全部 colcon 元数据。
4. 构建前再次校核清单和集合。发现变化时要求重新检查，不静默扩大范围。
5. 继承并冻结本次扫描环境。未实施自动 underlay 清洗，避免破坏已有工具链环境。
6. 取消只作用于已确认的本次会话进程组，等待子进程退出后释放锁；主动脱离会话的程序和外部强杀不提供完整恢复保证。
7. 清理提供 build 或 build+install 范围。保护当前工具的安装前缀与程序源码，拒绝根目录软链接，内部链接只删除自身。
8. 支持标准产物路径和已有 merged/isolated 布局。自定义路径、隐藏选择规则及部分默认配置组合明确拒绝，避免产生错误预览或误清理。
9. 合作实例互斥。外部直接运行的 colcon 不遵守本工具锁，仍需要避免与清理并发。
10. 默认配置及状态不再安装；新增 Python 子包由 find_packages 收集。现有 QSS 和图标安装规则保留。
